# Project Setup and Inference

Project setup has two phases. The filesystem phase is manager-owned. The
optional inference phase is read-only and produces a proposal.

## Phase 1: Materialize project setup

1. Resolve the repository root and confirm it contains a Git marker.
2. Ask the user to choose exactly one profile:
   - `local`: workflow state remains personal;
   - `shared`: rules, memory, sessions, skills, and compatible entrypoints may
     be shared;
   - `split`: rules and skills may be shared while memory, sessions, overlays,
     and local entrypoints remain personal.
3. Ask the user to choose target agents and whether `.syncprotect` should be
   managed.
4. Run:

   ```text
   agent-workflow setup preview --scope project --project <repo> --profile <profile> --output <plan>
   ```

   Add selected targets and sync-protection flags to this command. Present the
   exact materialized plan, conflicts, warnings, and ownership effects.
5. After explicit confirmation, run:

   ```text
   agent-workflow setup apply --plan <plan>
   ```

6. Run project doctor from the repository.

Never create agent-native files directly. Adapter entrypoints are generated by
the confirmed manager plan. Re-running setup is idempotent: generate a fresh
preview, preserve canonical user-owned content, and apply only missing or
unchanged managed outputs.

## Phase 2: Optional read-only inference

Offer this phase only after project setup succeeds or when the user explicitly
asks for a project description. It proposes content for
`.agents/project.md`; it does not authorize a write.

Inspect only enough evidence to describe the repository:

- root metadata such as Python, Node, Go, or Rust project files;
- the opening project description in a README;
- declared scripts, tasks, runtime versions, and formatters;
- a shallow main-package listing and detected entrypoints;
- referenced environment-variable names, never their values;
- the existence of tests, migrations, container, or deployment directories.

Propose concise sections for project purpose, runtime, commands, entrypoints,
structure, external integrations, conventions, environment constraints, and
explicitly unknown architecture areas. Cite observed files. Mark missing facts
as TODOs instead of guessing.

Do not read credentials, secret files, deep history, migration bodies, or
deployment values. Do not infer machine-specific or corporate rules from a
path prefix. Agent-specific instructions belong in overlays, not in the
portable proposal.
